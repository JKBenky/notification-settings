## 项目简介

游戏社区的通知系统长期存在两个顽疾：

1. **粒度太粗**：某一类通知（如推广）想单独关闭却关不掉，只能整体关闭；
2. **低价值打扰**：点赞、评论逐条推送、反复震动，迫使用户直接关闭全部通知权限。

整体关闭后，真正重要的通知（账号安全、关注游戏的开测提醒）也随之丢失，平台因此失去触达用户的渠道。本方案通过**三级分类 + 可独立开关**，在「减少打扰」与「业务触达」之间取得平衡。

## 设计目标

- 该响的响，不该响的不打扰；
- 每一类通知可单独控制；
- 重要通知不因用户反感推广而被连带关闭。

## 方案 · 三级通知分类

| 层级 | 类型 | 默认状态 | 策略 |
| --- | --- | --- | --- |
| **重要即时** | 账号与安全 | 开启 · 不可关 | 异常登录 / 改密 / 换绑；关闭系统通知后站内仍保留 |
| | 关注游戏的开测与更新 | 开启 · 可关 | 关闭时提示可能错过开测 |
| | 有人 @ 我 | 开启 · 可关 | 单独推送，不与点赞评论合并 |
| **社区互动** | 赞与评论 | 开启 | 同帖 1 小时内合并为一条摘要 |
| | 关注的人发布新内容 | 开启 | 仅消息中心红点，不发系统推送 |
| **平台推广** | 活动、礼包与内容推荐 | 关闭 | 留在「活动」入口；开启后每周 ≤2 条，22:00–8:00 不发 |

推广不删除、只静默——既减少打扰，也保留业务触达与用户的主动选择权。

## 原型功能

`index.html` 为可交互原型，结构如下：

- 顶部「允许通知」总开关，关闭后消息仍留在站内、仅不弹窗；
- 「重要即时 / 社区互动 / 平台推广」三个分组；
- 「账号与安全」开关锁定，其余各项可独立开关；
- 推广项文案随开关状态动态切换（默认不推送 ↔ 已开启）。

## 技术实现

- **纯原生 HTML + CSS + JS**，零依赖、无需构建，开箱即用；
- **明暗主题自适应**：基于 `color-scheme` 与 `light-dark()` 实现；
- **无障碍**：`role="switch"`、`aria-checked`、`aria-labelledby` 及屏幕阅读器文案；
- **动效克制**：尊重 `prefers-reduced-motion`，在减弱动效偏好下自动降级。

## 效果度量

上线后关注以下指标：

- 总开关被关闭的人数是否下降；
- 开测 / 更新推送的点击率；
- 「通知太多」类反馈是否减少；
- 消息中心「活动」入口的访问情况。
